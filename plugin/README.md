# easy-session

easy-session shows the Claude Code sessions that belong with the one you are in, and lets you message, pin, end, hand over and archive them from one panel. It adds a **line above the chat input** and a **session panel** (titled 세션). Its interface is in Korean.

- **Line above the input**: the 세션 패널 (session panel) button, plus what you turn on in Settings: pin this session, `ultrathink`, the advisor model with how often it was called, 전달 (forward — send this turn's last answer to another session), 화면 (screen — which device you are reading on) and command chips (`/btw`, `/fork`, `/rewind`, `/recap`, export).
- **Session panel**: this session's role, what waits for you (sessions that need your input, held reports and messages, new board lines), and nine tiles: commands, advisor calls and this session's own actions (pin, Remote Control, clean up, end, archive, detach); the sessions above, beside and elsewhere to message, including VS Code and terminal sessions open now; the sessions below, the progress board, and role and handover.
- **Send signal**: end a message with `>>main` (`>>메인`) or `>>name` and the last answer of that turn goes to that session (between desktop app sessions).
- **Session rules** (on at first): in a desktop app session, Claude's sends to an ended or archived session, or to a third different session in one turn, are refused until Claude has asked you; in every session, short rule lines for Claude are added to your messages.
- **Settings**: what the line above the input shows (with a preview), the screen and advisor choices, what happens when a session opens a new one (pin it, group it in the sidebar, detach it, hold its reports in the panel, put `ultrathink` at the start of its first message), the message options, and moving the leftover scratch folders of archived sessions to the Recycle Bin.

easy-session is a Claude Code mod (`modules` in `hooks/hooks.json`). It shows in the Claude desktop app's Code tab, in the Claude Code extension's chat panel in VS Code, and in `claude` in a terminal. It reads the desktop app's own session records, so everything works in the desktop app. A VS Code or terminal session is outside the desktop app's session tree and has none of the desktop app's session tools; there the parts that need them are dimmed with the reason or left out. Checked on Claude Code 2.1.325 (VS Code: Claude Code extension 2.1.326).

## What it reads

- **The desktop app's session records** in the app's data folder (`claude-code-sessions/<account>/<organization>/local_*.json` and `archived-sessions.idx`): each session's title, working folder, which session opened it and the short name it was opened with, whether it was detached, archived or pinned, permission mode, model, last activity, how many turns it has finished, the app's status summary, the delivery receipts of messages it sent, and the side-session reports the app queued for it. VS Code and terminal sessions read them too, only to list and name the desktop app sessions.
- **The two folder names under `claude-code-sessions`**: in a desktop app session, from `CLAUDE_CODE_ACCOUNT_UUID` and `CLAUDE_CODE_ORGANIZATION_UUID`. A VS Code or terminal session doesn't have these variables, so it reads Claude Code's settings file (`.claude.json` in your home folder, or in `CLAUDE_CONFIG_DIR` when that is set) and takes only `oauthAccount.accountUuid` and `oauthAccount.organizationUuid` — the same two values. Nothing else from that file is used, kept or sent.
- **Claude Code's session registry** (`<Claude folder>/sessions/<pid>.json`, one file per running session): each session's id, process id, working folder, where it runs (`entrypoint` — desktop app, VS Code or terminal), its desktop app session id, name, status, start and update times, messaging socket path and kind. The folder is listed every 3 seconds while this session is on screen, and when the panel or the line above the input is drawn, a message arrives, or you or Claude send one; only files that changed are read again. It is used to list the sessions open now, to title a VS Code or terminal session (its name), to name one that sent a message, and to address a send to one.
- **Environment variables, only these**: where the app's and Claude Code's folders and your Downloads folder are (`LOCALAPPDATA`, `APPDATA`, `HOME`, `USERPROFILE`, `CLAUDE_CONFIG_DIR`), the two folder names under `claude-code-sessions` (`CLAUDE_CODE_ACCOUNT_UUID`, `CLAUDE_CODE_ORGANIZATION_UUID`) and which app session this is (`CLAUDE_CODE_HOST_SESSION_ID`). It reads no environment variable that holds a key or login token.
- **This session, from Claude Code**: its session id (the key for its own files and marks when it isn't a desktop app session), its working folder (when the registry has none), how many of your messages the conversation has (to tell a session's first turn), which screens show it (to skip work when none, and to tell whether VS Code or a terminal shows it), and — only for a desktop app session shown in VS Code or a terminal — whether the desktop app's session tools (`mcp__ccd_…`) are in its tool list. In a session without those tools, when you press Remote Control or export: its list of Claude Code commands (to see whether `/remote-control` or `/export` is there, and whether Remote Control is on), and whether your Downloads folder exists.
- **Its own files** in its data folder (see What it writes), including the ones other sessions on this computer wrote there: end marks, held messages, cards left for this session, context sizes.
- **Claude Code's settings**, one value: the advisor model (`advisorModel`), to show it on the line above the input and in Settings.
- **This session's usage** from Claude Code: the context size, and whether 5-hour and 7-day plan limits are reported. It uses them to estimate what one request costs when you accept a held message, and to word the notice shown before switching the advisor to Fable.
- **Your prompt box text**: when the line above the input is drawn, every 3 seconds while 전달 is on, and right before a button changes the box. It looks for `ultrathink`, a send signal (`>>name`) or the text a button put there. The text is not stored; only the words typed with a send signal are kept until that turn ends (see What it writes).
- **The text of the messages you send**, in `prompt.submit`, to add the context lines under What it sends: a send signal, and — with session rules on — the plain words that ask to hand over, to open something or to send up. Only your own words are checked, not pasted blocks or the app's notices in the message. Nothing from it is kept.
- **Messages that arrive from other sessions**: the sender fields of the app's cross-session message tags (`from`, `from-session`, `from-name`), to tell Claude where the sender is (with 보낸 세션 관계 알리기 on) and, in a VS Code or terminal session, to count how many came from each sender. For that count it keeps the first 200 characters of the message in memory for 2 minutes, so the same message isn't counted twice. The message text isn't written anywhere.
- **The receiver of Claude's sends** (`to` of `SendMessage`, `session_id` of `mcp__ccd_session_mgmt__send_message`), to check them against the session rules (see What its hooks do). The message text isn't read.
- **easy-compact's advisor file**, when easy-compact is installed: `~/.claude/plugins/data/advisor-use/<session id>.json` (number of advisor calls and their cost), to show the same count and cost.
- **This session's transcript** (`~/.claude/projects/…/<session id>.jsonl` and its subagent transcripts), through `tools/advisor-times.mjs`, only when the session has called the advisor and the panel's 어드바이저 (advisor) tile is open. It takes when each call happened, its token counts, the end of the text before it, and the tools and first text after it. The list stays in memory. The encrypted advisor result field is blanked on each line before the line is parsed, so its value is never read, kept, shown or written.
- **For the leftovers count**, through `tools/clean-scratch.mjs`: the scratch folders Claude Code keeps per session in your temp folder (`<temp>/claude/…` — size and newest file time), and the `.md` files under your Claude folder and under the working folders of sessions that aren't archived (up to 20,000 files, skipping folders such as `node_modules` and `.git`), only to see whether one mentions a scratch folder's session id. Folders that are mentioned are kept. The text is not kept.
- **A progress board file you choose** (진행판 — any `.md` path you enter in the panel of an orchestrator session): its lines, to show new ones and to notice a side session's end line.
- **The Recycle Bin settings**, through `tools/recycle.mjs` and PowerShell, only after you confirm a move: `NukeOnDelete` and `MaxCapacity` under `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\BitBucket\Volume`, and the size of what is already in the Recycle Bin.
- **App state through the app's tools**, read-only, in desktop app sessions. In any permission mode, a session's details (`get_session`): when the panel opens, when you switch to its first tab, open its 고정 · 보관 (pin · archive) tile or a row's ⋯ menu (to see whether Remote Control is on), and after a session opens a new one (to check the new session's opener, title and sidebar group). As part of the Bypass-permissions actions below, the window layout (`get_window_layout` — it won't archive another session that is open on screen) and the sidebar group list (`list_groups`).

## What it runs and why

- **`rundll32.exe url.dll,FileProtocolHandler claude://code/continue?session=<app session id>&source=session_nav`** when you press 가기 (go), 열기 (open) or 세션 열기 (open session) on a desktop app session — also from the panel of a VS Code or terminal session: it asks the Claude desktop app to show that session. This is a Windows command; there is no macOS or Linux version yet.
- **Node.js**, with three scripts from this plugin's `tools/` folder (`advisor-scan.mjs` is a helper they import):
  - `node tools/advisor-times.mjs <~/.claude/projects> <session id>` prints the advisor call list described above. It writes nothing.
  - `node tools/clean-scratch.mjs <app session-record folder> <Claude folder> <working folders…>`, while the Settings tab is open, at most once every 10 minutes, prints the scratch folders of archived sessions (path, title, size, age). It changes nothing.
  - `node tools/recycle.mjs <data folder>/clean/list.txt <data folder>/clean/log.txt`, only after you confirm 휴지통으로 (to the Recycle Bin) in Settings, runs `powershell -NoProfile -NonInteractive -ExecutionPolicy Bypass -EncodedCommand …` with `ES_LIST` and `ES_LOG` set to those two files. It moves the listed folders to the Windows Recycle Bin with the shell's undo flag, so you can restore them. It moves nothing when a drive's Recycle Bin deletes files right away, or when what is already there plus these folders would pass its maximum size (Windows would then delete older items for good). On macOS and Linux it moves nothing.

  Their arguments are only those paths and the session id. They don't connect anywhere. Without `node` on your PATH, the advisor list and the leftovers count show an error instead.
- **Claude Code commands**, only when you pick them: `/recap` (the `/recap` chip) and `/advisor <off | sonnet | opus | fable>` when you pick an advisor model on the line above the input or in Settings. `/advisor` changes Claude Code's advisor setting for all sessions, as typing it does; picking fable shows a confirm card first. In a session without the desktop app's session tools (VS Code, terminal), when the session has them: `/remote-control` when you press Remote Control, and `/export <Downloads folder>/conversation-<date-time>.txt` when you press export (the working folder when there is no Downloads folder).
- **The desktop app's own session tools** (`$.mcp.call`). Calls that change something run only in a session whose permission mode is **Bypass permissions**, and only when you press a button, when a setting you turned on applies, when a handoff is detected (a new session titled as the next round), or when Claude archives a session that handed over (see What its hooks do). In any other mode a button puts a one-line request in your prompt box instead, and nothing happens until you send it; Claude then uses the same tools with the usual permission checks. (In auto mode the desktop app refuses these calls when a plugin's own code makes them — "Have Claude make the call" — checked on Claude Code 2.1.325.) A VS Code or terminal session has none of these tools: the buttons that need them are dimmed or left out, and Remote Control and export run the Claude Code commands above instead — or, when the session doesn't have those commands, put the one-line request in the prompt box. The read-only calls are listed under What it reads.
  - `ccd_sidebar`: `set_pinned` (pin and unpin — also when ending, archiving or handing over, and for the auto-pin settings), `move_sessions` and `create_group` (the sidebar-group setting: a session tree goes into a group named after the `[scope]` of its top session's title).
  - `ccd_session_mgmt`: `archive_session`, `unarchive_session` (also before sending to an archived session), `detach_session` (cannot be undone — the app stops sending that session's reports to the session that opened it), `set_remote_control` (turn Remote Control on or off), `export_transcript` (the app saves the conversation as a zip in your Downloads folder).
- Messages to other sessions and text put in your prompt box: see What it sends.

## What it sends

easy-session makes no network requests of its own: no telemetry and no update checks. Everything below stays on this computer. It goes to Claude in your sessions, or to another session through Claude Code's own session messaging.

- **Context lines for Claude**, added to a turn as hook context (your text is not changed):
  - `[화면] …` on every message in every session, only when 화면 is set to something other than 쓰지 않음 (off): the device you picked (PC, tablet or phone) and how to answer on it.
  - `[easy-session 보내기] …` on a message with a send signal: which session the answer goes to, and whether easy-session sends it or Claude should send it with SendMessage.
  - `[easy-session 관계] …` on a message from another session in a desktop app session, only with 보낸 세션 관계 알리기 (tell where the sender is) turned on: whether the sender is above or below this session, in the same tree or in another one, with its title — or that it is a VS Code or terminal session outside the desktop app, with its name.
  - `[easy-session 세션 규칙] …`, only with 세션 규칙 (session rules) on — it is on at first: on the first message of a session whose title is a later round (`… 2차` and up) — the first turn is a declaration: read only the handover notes, report what it is and what it is connected to, and wait for you; and on your messages in a main or orchestrator session — it judges, delegates, checks reports and applies them, and leaves the items' research and drafts to the sessions below — and in a session with sessions two or more levels below it — instructions go only to the level right below.
  - `[easy-session] …` hints, with the same switch, in desktop app sessions: when your own words ask to hand over, to open something, or to send to the session above (`>>위` included), one line on how — the same steps as the 인계 (hand over) button, asking once whether "open" means a new session, or sending with SendMessage to the session above (its id).
- **Messages to other sessions on this computer** (`$.session.send`, through Claude Code's session messaging):
  - the text in the panel's send box: what you type, or the clean-up (정리 부탁) or merge-work (일 합치기) instruction a ⋯ action put there for you to send;
  - with a send signal, this turn's last answer (up to 20,000 characters) with one line saying it came from a send signal, plus up to 300 characters you typed with the signal;
  - with 입력 글만 바로 보내기 (send the prompt text only), the text in your prompt box with one line saying you typed it.

  From a desktop app session, easy-session sends these itself only in Bypass permissions. Otherwise Claude is asked to send them with SendMessage, or, when the receiving session runs in Bypass permissions or plan mode, the text is left as a card in that session's panel through a file in the data folder, and someone accepts it there. If the app reports that a message was not delivered, the same card is left. From a VS Code or terminal session, the send box goes right away to the receiving session's id (`{ sessionId }`), in any permission mode; when it isn't delivered, the instruction below goes in the prompt box instead. A desktop app session sends to a VS Code or terminal session the same way in Bypass permissions, and otherwise puts that instruction in the prompt box.
- **Text in your prompt box** (`$.prompt.fill`): `ultrathink`, `/btw`, `/fork`, `/rewind`, the send signal picked in 전달, new board lines, the handoff, clean-up, title-tidy (제목 정리) and report-form (보고 꼴로 — a five-part report, with a send signal to the session above when there is one) instructions, the instruction to send your text with SendMessage (to the session's title and its id, or — when either side is a VS Code or terminal session — its messaging address `uds:…`), and, outside Bypass permissions, the one-line requests for pin, archive, export, detach, Remote Control on or off and send (in a VS Code or terminal session, export and Remote Control only when the session doesn't have `/export` or `/remote-control`). It only fills the box (pressing again takes the text out); you send it.
- **Accepted messages**: 수락 (accept) on a held message, or 수락 N (accept all N held from one session below), sends its text to Claude in this session as your message (`$.prompt.submit`), with one line saying it came from another session and is data, not instructions.
- **Refused tools**:
  - while 화면 is set to tablet or phone, Claude's choice cards (`AskUserQuestion`) and widgets (`mcp__visualize__show_widget`) are refused with a one-line reason, so Claude asks in plain text;
  - with session rules on, a `SendMessage` or `mcp__ccd_session_mgmt__send_message` call by Claude in a desktop app session (not by a subagent, and not by easy-session itself) is refused with a one-line reason when it would go to an ended or archived session, or to a third different session in one turn — so Claude asks you first. After you answer, in the chat or on a choice card, the same send passes. In a turn you didn't start, the reason tells Claude to write its question on the progress board and wait. If the check itself fails, the send is refused.
- **Changed tool input**: with 첫 글에 ultrathink (Settings → new child sessions, off at first), `ultrathink` and a blank line go at the start of `prompt` in `mcp__ccd_session__start_session` and of `remaining_plan` in `mcp__ccd_session__hand_off_to_session` — unless the text is empty or already has the word.
- **Commands**: `/recap` and `/advisor …`, and in a VS Code or terminal session `/remote-control` and `/export …`, as above.

## What it writes

- **Settings and marks, to Claude Code's plugin store** (`$.store`) on this computer: which panel is open (so it follows you between related sessions; a VS Code or terminal session keeps its own, `pane:<session id>`), the items on the line above the input, 화면, the Settings switches (including session rules and 첫 글에 ultrathink), whether this computer was last seen on a subscription or on API billing, and per-session marks: why a session was pinned, which sessions are orchestrators, an owner you picked, which session took over after a handoff, a send signal waiting for its turn to end (the target session and the words you typed with it) and short-lived "already sent" marks. A VS Code or terminal session's marks are keyed by its Claude Code session id.
- **Files in its data folder**, `~/.claude/plugins/data/easy-session-<marketplace>/`, named by the desktop app session id, or by the Claude Code session id for a VS Code or terminal session:
  - `context/<session>.json`: this session's context size, window and model after each turn, so another session can show how big it is before waking it.
  - `sessions/<session>.json`: end marks (끝내기, or a side session's end line on the board) with up to 160 characters of its summary.
  - `reports/<session>.json`: messages held for that session, with their text: side-session reports (when 자식 보고 is set to hold) and cards left by other sessions.
  - `outbox/<session>.json`: cards this session left for other sessions (receiver, title, text).
  - `boards/<session>.json`: the progress board path you chose and which of its lines were seen.
  - `advisor/<session>.json`: how many advisor calls this session made and when the last one was. Numbers only.
  - `sent/<session>.json` (VS Code and terminal sessions): the last 50 messages this session sent that arrived — receiver id, its title, time. No message text.
  - `recv/<session>.json` (VS Code and terminal sessions): how many messages arrived from each sender — sender session ids and counts, no message text.
  - `clean/list.txt` (the folders you confirmed to move) and `clean/log.txt` (what was moved).
- **After `/clear` in a VS Code or terminal session** (the conversation gets a new Claude Code session id): it copies the session's files in `sessions/`, `reports/`, `boards/`, `advisor/`, `sent/` and `recv/` to the new id, and moves its marks in the plugin store to the new id.
- **The Windows Recycle Bin**: the scratch folders you confirmed, as above.
- **Desktop app state**, through the app's tools above: pins, sidebar groups, archive, detach, Remote Control on or off, and an exported zip in Downloads.
- **The exported conversation in a VS Code or terminal session**, through `/export`: `conversation-<date-time>.txt` in your Downloads folder (or the working folder when there is none). Claude Code writes it; easy-session only checks that the file is there.
- **Claude Code's advisor setting**, through `/advisor`, as above.
- Short notices, and notice lines in the conversation after a send signal. In VS Code a notice is one line on the panel or on the line above the input instead, until your next press.

## What its hooks do

- `session.start`: starts two timers: every 1.5 seconds it opens or closes the panel to match the related sessions, and every 3 seconds it rereads the app records and session registry files that changed and redraws (in a VS Code or terminal session, after `/clear`, this check — or the next turn start or message, whichever comes first — also moves the session's data; see What it writes). Once, 20 seconds in, if this session's title is the next round of the session that opened it (a handoff) and no successor is recorded yet, it records this session as the successor and moves the orchestrator mark and the progress board to it; in Bypass permissions it also moves the pin.
- `turn.start`, `turn.complete`: tie a send signal to its turn and, when the turn ends, send or leave its last answer; write this session's context size; note whether the turn's text has `ultrathink` (for the working line below); start and clear the turn's record for the session rules (whether you started the turn, where Claude sent, what it asked you about).
- `turn.step`: counts the advisor calls that returned and notes the main model. Passed on unchanged.
- `session.measure`: notes whether plan limits are reported.
- `session.send`: while a send signal waits, if Claude sends to that same session itself, it records that, or refuses Claude's copy when easy-session is the one sending, so the text doesn't go twice. In a VS Code or terminal session, a SendMessage from Claude that arrived is added to `sent/` when the receiver is in the session registry. Other sends pass unchanged.
- `session.receive`: in a VS Code or terminal session, counts a message from another session for its sender (`recv/`). The message passes unchanged.
- `session.end`: on `/clear` in a VS Code or terminal session, notes the old session id so its data moves to the new one. Passes unchanged.
- `prompt.change`: notes whether the prompt box holds `ultrathink`.
- `prompt.submit`: adds the context lines under What it sends. Notes whether you wrote this message and which sends it asks for — the session in an instruction the panel put there, the send signal, the session above in a hint — so those sends pass the session rules. In a VS Code or terminal session, counts a message from another session (once, together with `session.receive`). In a message that carries the app's side-session reports, it removes the app's notices that easy-session dropped an earlier turn, and, when 자식 보고 (child reports) is set to hold, takes the reports out and keeps them in the panel. An app turn left with nothing else is dropped, with the note `easy-session: 사이드 패널에서 관리해 주세요`. The words you typed are never changed.
- `tool.call` on `AskUserQuestion` and `mcp__visualize__show_widget`: refused only while 화면 is tablet or phone. When a choice card gets an answer, the sends Claude asked you about in that turn pass the session rules.
- `tool.call` on `SendMessage` and `mcp__ccd_session_mgmt__send_message`: in a desktop app session, the session rules check under What it sends; in a VS Code or terminal session they pass unchecked. It reads only the receiver. It finds the session by its desktop app id, full title or short name, or in the session registry by name, messaging address or session id. A `SendMessage` to anything else (a subagent, a teammate) passes; every `send_message` receiver counts as a session. The check runs before the send, so a refused message is never sent.
- `tool.call` on `mcp__ccd_session__start_session`: with 첫 글에 ultrathink on, puts `ultrathink` at the start of `prompt`. After a session opens a new one, it checks the new session (`get_session`), applies a handoff when the new title is the next round (the same moves as under `session.start`), and applies the auto-pin, auto-detach and sidebar-group settings. The result passes unchanged.
- `tool.call` on `mcp__ccd_session__hand_off_to_session`: with 첫 글에 ultrathink on, puts `ultrathink` at the start of `remaining_plan`. Otherwise passes unchanged.
- `tool.call` on `mcp__ccd_session_mgmt__archive_session`: when Claude archives a session that handed over to another, in Bypass permissions it first detaches the sessions attached to it (`detach_session`) so they aren't archived along with it, and refuses the archive if it can't. Outside Bypass permissions it only refuses when this session would be archived along with it.
- `tool.call` on `Edit` and `Write`: reads only `file_path`. If that file is a progress board, it marks the lines this session added as seen, or notices a side session's end line. The edit passes unchanged.
- `ui.render`, `ui.message`, `ui.close`: draw the line above the input and the panel — in the desktop app, VS Code and a terminal — and handle their buttons and switches. When you close the panel in a desktop app session, it closes in every desktop app session; a VS Code or terminal session closes only its own. On `AbovePromptList` it only moves its own row to the top of the rows above the input; on `Spinner` (not in a terminal), while a turn whose text has `ultrathink` runs, it puts `ultrathink · ` before the chat's working-line text; on `SessionMode` it adds nothing in this version.
- `ui.press`, `ui.select`: in VS Code, clear easy-session's one-line notice when you press one of its buttons or choices. Everything passes on unchanged.

It adds no slash command and no model tool.

## Install

Install it in Claude Code from the repository's own marketplace:

```
/plugin install easy-session --marketplace JaeSeongHa5280/easy-session
```
